# Michael Solomon - GitHub profile setup

This pack is designed for a personal GitHub account and a public profile README.

## 1. Create and secure the account

1. Create a personal account at [github.com](https://github.com/).
2. Choose a professional username that will still fit if your job title changes. Good patterns to check include:
   - `michael-solomon-sec`
   - `msolomon-cyber`
   - `michael-solomon-infosec`
3. Verify the account email.
4. Use a unique password and enable two-factor authentication. Add a passkey if available to you.
5. Keep the recovery codes in a secure password manager or offline recovery location.

Do not put a phone number, home address, client name, private incident detail, production configuration, access token, or certification ID in a public repository.

## 2. Use these profile fields

| Field | Recommended value |
| --- | --- |
| Name | Michael Solomon |

| Location | Philippines |

| Website | Add LinkedIn or a portfolio site when ready |
| Public email | Use a business-facing address only if you want it indexed publicly |

Suggested profile photo: a clear, professional head-and-shoulders image with a simple background. GitHub recommends an image around 500 by 500 pixels; PNG, JPG, and GIF are supported.

## 3. Publish the profile README

GitHub displays a profile README when:

- the repository name exactly matches your username;
- the repository is public; and
- a non-empty `README.md` is in the repository root.

After your account is ready:

1. Create a new **public** repository whose name exactly matches your GitHub username.
2. Upload this pack's `README.md` to the repository root.
3. Upload the `assets` folder without changing its name or structure.
4. Commit the files with a message such as `Create professional cybersecurity profile`.
5. Open your GitHub profile and confirm that the banner and README display correctly.

Official references:

## 4. Make the first profile credible

- Do not add empty or copied repositories merely to make the profile look busy.
- Publish original, sanitized artifacts that show how you think and work.
- Write a useful README for every repository: problem, audience, approach, scope, limitations, and safe usage.
- Use synthetic data for dashboards and examples.
- Remove employer branding, client references, IP addresses, domains, ticket data, screenshots, keys, and secrets.
- Pin only the strongest public repositories once they contain real work.

The accompanying `PORTFOLIO_ROADMAP.md` proposes credible first repositories based on the attached CV.
